Финальная сборка/пакет/доставка остаются ответственностью основного агента.

## Узкая окончательная перепроверка контекста и restore

Дополнительно закрыты два ранее отмеченных остатка. `LifeCore.tick` сохраняет последний наблюдённый context (`crates/lifecore/src/lib.rs:245`–`:253`); feedback без pending_attention использует его (`:328`–`:330`). До первого tick и после restore context остаётся неизвестным с нулевым bias. `MemorySystem.record` обновляет active_hours только при bias > 0.5 (`memory.rs:116`–`:121`), поэтому неизвестное время больше не трактуется как полночь. Обычный feedback после наблюдения 18:00 попадает в 18-й час, а сохранённый pending продолжает использовать собственный исходный context.

`LifeCore::restore` теперь явно вызывает `restored.learning.body.clear_transients()` (`lib.rs:709`), поэтому незавершённая обучающая пара, краткий stalled-state и доверие очищаются также для in-memory `restore(snapshot())`, без зависимости от serde skip. Обученные параметры и история остаются сохранёнными.

Независимо исполнены два новых regression-теста: `unsolicited_feedback_uses_observed_clock_and_unknown_time_is_not_midnight` и `in_memory_restore_discards_unfinished_body_prediction`; каждый — **1 passed, 0 failed**. `git diff --check` прошёл. Новых замечаний по этому ограниченному изменению нет.

## Исторический вердикт первого прохода

Новые ограниченные learners действительно подключены к LifeCore/runtime и сохраняемому состоянию; это не только интерфейсные поля. Исправления знака reward, затухания gesture/negative, однократной консолидации и restart trace в целом соответствуют прежнему аудиту. Однако нужны исправления ниже до утверждения, что адаптивный ответ в живом приложении соответствует выбранной стратегии и что offline видит тот же R12-вход.

## R1 — P2, исправлено: выбранный смысл и тихая длительность теряются в ExpressionDirector

**Места:** `crates/lifecore/src/adaptive_learning.rs:187`–`:208`; `crates/lifecore/src/language.rs:560`, `:599`–`:605`, `:629`; live вызов `app/src/main.rs:4755`–`:4758`.

`apply_strategy` задаёт для стратегии 0 `AcknowledgeContact`, hold=0.18, pulse=lean=0; для стратегии 2 `InviteRepeat`, новый голос и pulse. Но `direct_world` выбирает semantic intent по исходному `plan.reason`, не по изменённому communicative_intent. Для SoftTouch он остаётся Contact у обеих стратегий. Director безусловно заменяет hold на >=0.8 и может вернуть pulse/lean тихому ответу. Learner затем сохраняет outcome под выбранной стратегией, хотя её значимые свойства были изменены после выбора.

**Реальное воспроизведение:** временный публичный lifecore probe создаёт SoftTouch, применяет стратегии 0/2 и пропускает через ExpressionDirector. Вывод:

```text
strategy=0, intended=AcknowledgeContact, rendered_intent=Contact, hold_before=0.18, hold_after=0.8225
strategy=2, intended=InviteRepeat, rendered_intent=Contact, hold_before=0.25, hold_after=0.8225
```

**Исправление:** единственный согласованный semantic meaning для strategy/reason/phrase, сохранение тихих ограничений последующими слоями. **Проверка:** полный plan→director→VITA→phenotype путь для 0/1/2, включая Focus/sleep; сравнить итоговый смысл, длительность, голос и движение, а не лишь локальные поля learner.

## R2 — P2, исправлено: семантическая мимика ответа стирается финальным phenotype

**Места:** `app/src/vita_runtime.rs:590`–`:609` и далее применяют plan.expression; `app/src/nervous_system_runtime.rs:218`–`:235` применяет phenotype после VITA; `crates/lifecore/src/phenotype.rs:1033`–`:1043` перезаписывает gaze при наличии своего и полностью присваивает `intent.expression=self.expression`, сохраняя только mouth_open/blinks. `resolve_actuation` объединяет только interaction/body, а не семантическую мимику.

**Доказательство:** это прямое присваивание после выражения конкретного ответа. Следовательно, даже исправленный ExpressionDirector не гарантирует, что его выбранная мимика попадёт в тело. Паттерн существовал раньше, но новые обучаемые стратегии усиливают проблему причинного учёта: ack по таймеру active plan не доказывает, что описанные каналы стратегии исполнены.

**Исправление:** определить одного финального владельца композиции: bounded semantic overlay после phenotype либо семантический план как вход phenotype director. Не делать два конфликтующих независимых override. Учитывать маски каналов и разрешённые ограничения тихого ответа. **Проверка:** задать заведомо различающиеся semantic expression и phenotype baseline; проверить конечный опубликованный intent, защитные пределы, blink/mouth callback и acknowledgement по нему.

## R3 — P2, исправлено: моторный вектор не соответствует Flee/Orbit, портит credit и обучающие пары

**Места:** `app/src/nervous_system_runtime.rs:271`–`:285`; `crates/pet_body/src/lib.rs:347`–`:348`; `crates/pet_body/src/locomotion.rs:129`–`:137`; `crates/lifecore/src/adaptive_learning.rs:422`–`:450`.

R12 efference_copy берёт радиальное направление к target для всех locomotion. Flee физически задаёт отрицательное направление, а Orbit — тангенциальное с радиальной коррекцией. Новая квитанция Morph требует `motion.dot(commanded)>0`; успешное Flee при движении от цели закономерно не получает Flee credit. Orbit при правильном касательном движении получает нулевой/неправильный знак. BodyLearning.begin исправляет знак Flee вручную, но кодирует Orbit как Seek и не включает тип режима в признаки. Одинаковый набор x тогда может описывать разные реальные команды.

**Исправление:** получать из общего моторного исполнителя нормированную допущенную команду после ограничений. Для предсказания использовать только известную до перехода команду/состояние, target следующего состояния не должен попасть во вход. **Проверка:** Seek/Flee/Orbit из одинакового физического состояния; знак/касательная/единицы совпадают с командой исполнительного слоя; правильное выполненное движение подтверждает ожидаемый Morph command. Удержание/запрет не подтверждает неисполненное движение.

## R4 — P2, исправлено: общий prepare/apply пока не даёт одинаковой обратной связи live и replay

**Места:** live `app/src/main.rs:2224` публикует feedback после каждого physical substep; pointer `app/src/pointer_replay_runner.rs:168`–`:170` и evolution `app/src/evolution_runner.rs:967`–`:970` публикуют только на cognition tick. `crates/pet_body/src/lib.rs:412`–`:413` вычисляет jerk как разность с предыдущей публикацией без нормировки dt. Pointer принимает plan прямо (`:194`), тогда как live/evolution пропускают его через ExpressionDirector (`app/src/evolution_runner.rs:1001`).

**Эффект:** одинаковая траектория ускорения создаёт live delta последнего substep и offline delta за шесть substeps; разные значения уходят в R12. Pointer также получает другие hold/expression semantics. Unit-тесты learner этого не видят, поскольку подают уже готовые pairs/acks вручную.

**Исправление:** единая публикация по завершению физического шага и явно согласованная временная мера jerk; одинаковая стадия ExpressionDirector в проверочном runtime. **Проверка:** сравнить BodyFeedbackV2/R12 snapshots и конечный response packet на записанной детерминированной физической ленте. Отдельно замкнутые сценарии для пользы поведения; проход unit-тестов не называть полной live/offline parity.

## R5 — P2, исправлено: новый одинарный слот Morph feedback перезаписывает ещё не применённый исход

**Места:** `crates/morph_brain/src/lib.rs:1517`–`:1524` (`note_feedback`) присваивает pending_feedback/pending_command/pending_trace; обработка только на 100 ms update (`:359`–`:363`). После feedback last_command очищается.

**Контрпример из кода:** ack Play → reward +1 → ack Groom → reward -1 до ближайшего update. Второй вызов полностью заменяет ожидающий Play credit, поэтому первая реальная оценка исчезает. Повторный feedback без нового ack ещё хуже: заменяет pending_command на Idle и может стереть уже допустимый outcome. Старое суммирование тоже не обеспечивало корректную атрибуцию; возврат к нему не исправление.

**Исправление:** ограниченная очередь замороженных credit records или немедленное потребление каждого operant outcome с зафиксированным trace; явная дедупликация, если это повторная доставка того же события. Система может осознанно отвергать лишние события по документированному пределу, но не молча стирать уже принятый исход. **Проверка:** два разных ack+outcome в одном 100 ms интервале обновляют соответствующие команды один раз; повтор без допустимого ack не уничтожает предыдущую запись. Статический контрпример, отдельный исполнительный тест этим агентом пока не запускался.

## Проверка заявлений о пяти способностях

1. **Контекстный ответ:** веса и история реально меняются только после acknowledged pending outcome, есть работающий hard gate по work/sleep/stress. Но полная семантика стратегии требует R1/R2; тесты напрямую acknowledge не доказывают физическое исполнение.
2. **Модель тела:** реальная ограниченная линейная регрессия, два режима contact/no-contact, отдельные train/validation, число наблюдений, bounded speed reduction. Моторные признаки требуют R3. Это пока прогноз четырёх величин и ограничитель повторного усилия, не универсальное обучение схеме тела/навыку.
3. **Использование опыта:** есть ближайшая история с ограниченным blending и кратким refusal. Это контекстная поправка к выбору, не многошаговое планирование или полноценное эпизодическое воспоминание. Число реальных observations при retrieval не растёт.
4. **Любопытство:** есть статистически ограниченный progress signal и небольшой бонус двум существующим action. Нет доказательства, что питомец выбирает именно обучаемую область среды: сигнал агрегирован по свободному режиму, а отдельные варианты SelfPlay/ExploreScreen не имеют своих context-progress прогнозов. Корректная формулировка — «интерес ограниченно усиливается, когда модель тела показывает прогресс». Unit noise-тест не заменяет сравнение замкнутых сценариев known/learnable/noise с policy baselines.
5. **Повторение в покое:** повторяются только train samples, validation и real-observation counters не увеличиваются, количество bounded. Но `.rev().step_by(3).take(8)` — детерминированная разреженная выборка последних данных, не равномерный replay по всему буферу, как написано в комментарии. Можно исправить выборку либо честно назвать его ограниченным повторением недавнего опыта. Улучшение после отдыха отдельно ещё не доказано live-сценарием.

## Прочие ограничения, не блокирующие исправления выше

- **Уточнение после перепроверки:** explicit body.clear_transients теперь действует и для persisted, и для in-memory restore; соответствующий regression-тест прошёл. Exact checkpoint по-прежнему не реализован и не должен обещаться.
- **Исправлено после перепроверки:** feedback без pending использует последний наблюдённый context, unknown startup context исключён из active_hours. Regression-тест неизвестного времени и 18:00 прошёл; детали приведены выше.
- Общая event envelope с идентификатором реальной обратной связи для всех learners ещё не появилась: защита ResponseLearning по response_id не доказывает exactly-once для старых MicroBrain/habits/memory apply_feedback. Утверждать «все C1–C9 полностью закрыты» без оговорок преждевременно: C7 закрывается для части признаков после R3, C4 — только после проверки cadence/pipeline.
