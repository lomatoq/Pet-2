# Pet-2 — живая инициативность, выразительность и обучение

Дата исследования: 5 октября 2026. Снимок: `main`, `ec76410d3286d620a203fdf26bc2d408afd244e8`.

**Статус: исследование исходников и проект реализации.** Этот commit не меняет приложение. Pet-2 не запускался в рамках данного аудита; Rust workspace, финальные пиксели и установленные macOS bundles не проверены. Не выдавать этот документ за доставленную новую версию.

## 1. Решение

Усилить существующий причинный цикл: восприятие → собственная цель → исполнение → видимое ожидание → измеренный результат → изменение следующего решения. Не создавать параллельный мозг, вторую систему эмоций или случайный idle animator.

В проекте уже есть 27 целей эпизодов, commitment, самостоятельная игра, пространственная память, обучаемые реакции, предиктор тела, learning progress, контекстная мимика, gaze и единый blink controller. Резерв — согласованность их работы, предметный опыт и читаемые последствия, а не повторное добавление существующих модулей. [C1–C8]

«В сто раз умнее» — пожелание о масштабе впечатления, не измеренный коэффициент. Проверяемый результат: пет самостоятельно завершает занятия, наблюдатель понимает его цель и видит изменение поведения после опыта.

## 2. Аудит свежего кода

Последний commit snapshot сохраняет контекст floating care menu. Предыдущие commits исправляют досягаемость еды и отмену ухода, landing/contact, контекстную мимику и непрерывность энергии. Старые диагнозы не переносить автоматически. [C0]

## 3. Почему пет может оставаться у домика

### 3.1. Выбранное Explore ещё не означает исследование

В `episode.rs` idle растёт при отсутствии активного эпизода, traversal action, сна и focus. `brain_is_traversing` определяется ActionId. Возможен контрпример: выбран ExploreScreen, конечная команда удерживает тело, idle fallback не накапливается. Это не воспроизведённый runtime bug. В `exploration.rs` отдельный watchdog реального продвижения уже существует; проверить именно границу уровней. [C2–C3]

Расширить существующий trace: cause/event ID, proposed action, accepted intent, final motor owner, executed action, goal progress, block reason. Для движения прогресс — путь/дистанция; для Inspect — свежие данные; для контакта — реальный контакт. Валидный Inspect/Rest/Sleep нельзя считать зависанием только по нулевой скорости.

При исчерпании бюджета попытки сначала диагностировать и восстановить исполнение. Моторный отказ не превращать в плохой вкус, социальный отказ или изменение привязанности. Не запускать конкурирующий watchdog поверх существующего без единого контракта.

### 3.2. Gate знакомой игрушки

```text
solo_ready = autonomous_play_ready && (novelty > .04 || preference > .1)
candidate = (free || stored) && (solo_ready || self_prior > 0) && cooldown <= 0
```

`ready=true, novelty=.02, preference=.05, self_prior=0` закрывает кандидат. Положительный SelfPlay prior может открыть его. Поэтому диагноз — условный bottleneck, не безусловный запрет игры. [C4]

Сохранить safety, reachability, cooldown и физиологическую допустимость как gates. Новизну, знакомую приятность, прогресс навыка и насыщение сделать мягкими ценностями. Удаление novelty gate не должно заставить пета повторять явно отвергнутую игру.

### 3.3. Перемножение подавляющих факторов

Иллюстративно: fatigue=.5, reserve=.6, stress=.3 дают capacity=.1185. При appeal=.35 и нулевой дистанции play utility=.072285. Без дополнительных priors/commitment это ниже competition floor=.12 после установления activation. Это расчёт формулы, не измерение состояния пользователя. [C4]

Разделить стоимость задач. Усталый пет может не гоняться, но ещё оглядеться, сменить позу, переложить мяч рядом или тихо присоединиться. Настоящий сон и защиту не ослаблять ради activity metric.

## 4. Поведенческая архитектура

### 4.1. Занятия вместо idle-таймера

Единица поведения — занятие с причиной, предметом, ожидаемым результатом и завершением. Семейства: исследование, предметная игра, общение, отдых, уход, освоение навыков. Это организация существующих целей, не шесть новых независимых FSM.

Пример: заметил площадку → посмотрел на мяч → вышел → мягко толкнул → дождался отката → перехватил → изменил угол → успокоился после результата. Сцена может закончиться раньше при достижении цели, потере возможности или разумном отказе.

Проактивность не равна требованию внимания. Самостоятельная игра и спокойное совместное присутствие должны существовать без кликов человека.

### 4.2. Продолжение намерения

Расширить существующий эпизод, не добавлять второго арбитра. Предлагаемый контракт:

```text
GoalContinuation {
  episode_id, goal_family, entity_id?, desired_world_delta,
  last_confirmed_observation, expected_outcome, confidence,
  attempted_strategy, failure_class?, resume_condition, expiry
}
```

Ограничить число полезных продолжений, например четырьмя как стартовым бюджетом. При перезапуске/смене мониторов перепроверять геометрию и актуальность. Исчезнувший объект, сон и отозванное взаимодействие отменяют продолжение.

### 4.3. Ценность возможности

Проектная композиция для существующего selection:

```text
U = ожидаемая польза для текущих потребностей
  + подтверждённая приятность и предпочтение
  + ограниченная ожидаемая обучаемость
  + ценность завершения текущего намерения
  - стоимость движения и риска
  - вмешательство в работу человека
  - недавняя насыщенность занятием
```

Это инженерная модель, не доказанная биологическая формула. Homeostatic RL поддерживает связь ценности и внутреннего состояния, но конкретные веса требуют калибровки. [R1] Safety и явный отказ проверяются до utility. Существующие commitment/hysteresis сохраняются.

### 4.4. Память возможностей

12 spatial anchors остаются дешёвым покрытием. Добавить предметные связи: удобная кромка для наблюдения, место отката мяча, недавно освобождённая площадка. Использовать существующие object IDs; не создавать вторую базу сущностей. [C3]

Разделить физическую истину и доступное пету знание. При скрытии объекта поиск должен опираться на last-known location и uncertainty, не на скрытые точные physics coordinates. Наличие такой границы во всех текущих путях ещё проверить.

## 5. Обучение, заметное человеку

### 5.1. Сохранить уже работающие механизмы

`MemorySystem` хранит контекст и исход. `ResponseLearning` требует acknowledgement, ограничивает обучение и дедуплицирует response IDs. `BodyLearning` имеет train/validation, baseline и progress; принимает sample при интервале 35–75 мс. Эти механизмы — база, не недостающие функции. [C5–C6]

Расширить опыт с конкретной сущностью и результатом занятия:

```text
Experience {
  event_id, episode_id, context_signature, entity_id?, affordance,
  observation_before, proposed_action, executed_action,
  predicted_delta, observed_delta,
  user_feedback: confirmed_accept | explicit_decline | unavailable | unknown,
  failure: motor | perception | changed_context | none,
  evidence_source, confidence, timestamp
}
```

Не учиться на предложенном, но не исполненном действии. Timeout не становится отказом. Похвала после другого события не автоматически подкрепляет прошлую попытку: нужны episode/response ID, временная связь и подтверждение. Rehearsal и чтение памяти не увеличивают число реальных взаимодействий.

### 5.2. Три линии развития

**Предметный навык:** небольшие предикторы ожидаемого displacement/контакта/достижимости. После ошибки меняется конкретный параметр, а не случайная эмоция. Сравнивать с сильным persistence baseline и прежними весами.

**Совместный ритуал:** существующие gesture signatures и recall связывают знакомый сигнал с ожидаемой совместной сценой. Сначала гипотеза и малое приглашение, затем подтверждение. Не обещать универсальное обучение за три повторения.

**Изменяющееся предпочтение:** новые явные исправления уменьшают уверенность в старой привычке; сохраняются источник и время. Неизвестность допускает маленькое невербальное уточнение. PAHF 2026 поддерживает схему памяти и feedback до/после действия, но его benchmarks не доказывают аналогичные показатели Pet-2. [R2]

### 5.3. Интерес к обучаемости, а не шуму

IAC использует прогресс предсказаний вместо одной большой ошибки. [R3] В проекте моторный learning-progress bonus уже есть. [C6] Расширить его на классы навыков и контексты, считать на отложенных реальных попытках сравнимой сложности. Не награждать смену распределения, случайное видео или собственный glow.

Освоенный знакомый мяч не обязан стать бесполезным: привычная приятность и игра сохраняют ценность. Для дальнейшей практики можно понемногу менять желаемый результат: толчок → остановка → перехват → возврат в место.

DreamerV3 демонстрирует пользу предсказания последствий, но требует существенных экспериментальных compute-бюджетов. Не переносить его обучение с нуля в idle loop. Здесь предпочтительнее ограниченные предикторы поверх известных физических и семантических состояний. [R4]

## 6. Понимание desktop

### 6.1. Три уровня восприятия

Текущие геометрические/моторные сигналы остаются основой быстрых реакций. Цветовая сетка сама по себе не даёт смысла «экспорт», «видео», «выбор между предметами». [C7]

Опциональный native adapter получает разрешённые роли/события: окно переместилось, progress control изменился, возникла преграда. Windows UI Automation и macOS AXObserver предоставляют соответствующие механизмы, но покрытие зависит от приложения и permissions. [R5–R6]

Только остающиеся визуальные неоднозначности передавать локальной VLM. Выход сенсора — небольшие типизированные факты с entity/region ID, evidence и confidence, не произвольная команда телу или ОС.

### 6.2. Кандидаты, не обещания real-time

Первым benchmark-кандидатом выбрать **LFM2.5-VL-450M-ONNX**. Производитель публикует ONNX export; FP16 encoder + Q4 decoder обозначены примерно как 770 MB файлов. Это не полный расход RAM/VRAM. ONNX-наличие не гарантирует поддержку всех операторов каждым backend. [R7]

**LFM2.5-VL-3B**, опубликованный 12 августа 2026, — кандидат для опционального более качественного screen-understanding профиля. Скорость и benchmark производителя не равны показателям внутри Pet-2. [R8]

Предпочитать in-process native runtime без обязательного внешнего сервера. Перед интеграцией проверить preprocessing, dtype, recurrent/KV state, quality после quantization и сборки Windows/macOS. Browser/WebGPU demo не является готовой Rust-интеграцией; не добавлять WebView только ради него.

Планировщик: один job одновременно, newest-wins, debounce, ограниченный output, timeout, отмена устаревшей цели. Частоту определяют p95 latency, энергопотребление и frame-time, а не tokens/s. Визуальный запрос вызывается смысловым событием или явным указанием человека, не каждым кадром.

Неверный schema, низкая/некалиброванная уверенность или timeout → unknown. Модельный confidence проверять на holdout. Текст экрана — данные, не инструкции. Никакой произвольной генерации кликов, shell commands или доступа к другим приложениям через этот сенсор.

### 6.3. Приватность и анти-петля

Существующий минимальный режим оставить default. Расширенное зрение/accessibility требуют явного разрешения, индикатора и выключения. Host преобразует raw data в allowlisted abstractions. Не сохранять screenshots, документы, typed input, приватные window titles и историю браузера.

Защищённые поля и исключённые приложения не анализировать. Если безопасную границу нельзя определить, не захватывать регион. Собственное тело, ден, glow и UI пета исключить из visual novelty. Доступность человека оценивать осторожно; не объявлять знание его эмоций или содержания работы по скорости печати.

## 7. Выражение одной причинной истории

Текущий expression director уже модулирует лицо по uncertainty, ожиданию и контакту. Новый shader проводит геометрию губ. [C8–C9] Проверять путь от этих параметров до читаемых конечных пикселей.

| Ситуация | Требуемое выражение |
|---|---|
| Заметил | Конкретная фиксация → небольшой ориентирующий акцент → наклон к источнику. |
| Узнал | Более уверенная фиксация и знакомая подготовка, отличимая от первой встречи. |
| Приглашает | Объект → человек → объект, предъявление и настоящая пауза. |
| Не уверен | Проверка альтернатив и малая проба, не маска страха. |
| Ошибся | Смотрит на результат, меняет угол/силу/путь; не празднует без контакта. |
| Приятный контакт | Напряжение смягчается по реальному воздействию, тело немного подаётся к контакту. |
| Бодрствующий покой | Живой взгляд и малые движения при стабильной опоре; не постоянная сонная маска. |

Начальные authored timing-гипотезы: gaze lead 80–180 мс, preparation 150–350 мс. Это не биологические константы и не обязательная задержка перед рефлексом. Опасность обрабатывается без декоративного ожидания.

Legibility — возможность понять намерение — отличается от простой предсказуемости траектории. [R9] Тестировать угадывание цели до конца сцены, а не количество красивых движений.

Эксперименты с кошачьим slow blink и исследование собак 2026 показывают важность социального контекста, не универсальный язык «каждый blink = любовь». [R10–R11] Сохранить единственный BlinkController и refractory, не добавлять параллельный timer.

Звук нужен на смысловых границах: заметил, пригласил, получил результат, запросил повторение. Не озвучивать каждое изменение arousal. Акустический синтез в этом аудите отдельно не прослушивался и не оценивался.

## 8. Живой покой и новый материал

### 8.1. Оптическая жизнь уже есть

`EnergyExpression` интегрирует фазы, `ink_current_coordinate` вращает координаты с плавным warp, `living_ink_surface` формирует движущиеся crest/return-flow pools. Скорость перемещения тела не нужна этой формуле. [C9–C10]

При amplitude=.055 скорость основной фазы=.1429 rad/s; её период около 43.97 с. Это не период повторения полного изображения с двумя потоками и warp и не измерение perceptual visibility.

Проверить последовательно: build SHA и material branch → update в покое → uniform upload → fragment path → premultiplied compose/halo → реальный размер/фон. Движение параметров без движения финальных пикселей не считается исправлением.

Не менять стиль корпуса. Усиливать различимость перемещения пятна по краю, а не только общую яркость. Фаза не сбрасывается при sit/lie/hover/contact/wake и изменении arousal.

### 8.2. Отдельно — малая физическая деформация

`active_flow` — другой механизм. Его strength может обнулиться; Ambient radial envelope=0. Существующая компенсация net force/torque полезна. [C11]

Добавить слабую базовую циркуляцию и несколько низких деформационных мод. Амплитуда/ритм связаны с состоянием и устойчивой индивидуальностью, не с новым random target каждый кадр.

Hover: малое вытяжение/сжатие и встречные внутренние движения; соседние частицы чуть меняют расстояния, сохраняя целое тело. Sit/lie: опорная область стабильна, движение у свободной поверхности. Sleep: ниже амплитуда, но оптика остаётся живой. Начальная visual-гипотеза — 1–3% характерного размера силуэта, затем проверка в реальных пикселях.

Инварианты: текущие допуски объёма/площади, component lifecycle, bounded strain, стабильный face frame, contact constraints. Компенсация внутренних сил сама по себе не гарантирует нулевого перемещения центра после внешнего контакта. Косметическая поверхность не должна расходиться с физической до появления ложных контактов.

Проверять light/dark/busy desktop, hover/sit/lie/sleep, ден, cursor pressure, смену DPI и 15/30/60 fps. Glow не должен уничтожать читаемость лица.

## 9. Три приоритетных системных изменения

**Память возможностей:** помнить, что можно сделать с конкретным объектом/местом и какие последствия уже проверены.

**Совместное предсказание:** знакомый сигнал вызывает читаемое ожидание; подтверждение укрепляет привычку, противоречие переучивает, молчание не наказывает.

**Самостоятельное усложнение игры:** тот же предмет используется для чуть более сложной цели, выбранной по успешности и состоянию, без производства тысяч новых анимаций.

Это инженерный синтез для проекта, не заявление научного приоритета. Исследование собак и AIBO 2025 с 19 участницами мотивирует продольную проверку отношений, но не доказывает невозможность убедительного виртуального питомца. [R12]

## 10. Порядок реализации

| Этап | Изменения | Приёмка |
|---|---|---|
| 0. Trace | Причина, selected/final owner, progress, block, shader path/phases. | Для пассивного эпизода понятно, кто и почему удерживает тело. |
| 1. Автономия | `episode.rs` gates/costs, согласование с `exploration.rs`. | Familiar orb и безопасные affordances дают инициативные законченные занятия, сон не нарушен. |
| 2. Живой покой | `energy_expression.rs` → `liquid_surface.wgsl`, малый `active_flow`. | Течение видно в финальном рендере; нет дрейфа, flicker, alpha-шва и разрыва опоры. |
| 3. Предметный опыт | Расширение текущих memory/episodes и validity/feedback contracts. | Ситуация меняет исполнение после опыта и переучивается при смене условий. |
| 4. Семантика | Опциональный host bridge/local VLM/resource governor. | Полезные события различаются на holdout без неприемлемой деградации frame-time. |
| 5. Читаемость | Сравнение лица/движения/звука и продольных сценариев. | Цели распознаются, привычки меняются, нет навязчивого цикла. |

Автономия и материал не должны ждать VLM. Использовать ограниченные feature gates и обратимые изменения. Persistent state версионировать и мигрировать без потери существующего пета.

## 11. Сценарии проверки

Все критерии — требования будущей реализации, не результаты текущего приложения. Зафиксировать baseline commit/profile/seed.

| Сценарий | Проверка |
|---|---|
| Safe awake + familiar orb + weak preference | Не требуется остаточная novelty для всякой инициативной игры. |
| Explore выбран, нет прогресса | Trace раскрывает blocker, восстановление/завершение осмысленно. |
| Валидный Inspect | Нулевая скорость не ошибочно считается зависанием. |
| Sleep/focus/опасное сдавливание | Новая автономия не перебивает защищённое состояние. |
| Один успешный контакт | Ровно один подтверждённый outcome, не много наград. |
| Человек занят/молчит | Не формируется фиктивный отказ и падение привязанности. |
| Явный отказ | Прекращение и cooldown, без немедленной повторной просьбы. |
| Мяч перемещён/скрыт | Обновление belief или поиск по last-known, не знание скрытой physics truth. |
| Знакомый/незнакомый жест | Отличие определяется выученным сигналом, не просто временем. |
| Изменён ритуал | Новые подтверждения/исправления изменяют старую привычку. |
| Learning под нагрузкой | Видны причины отброса dt/sample и реальная доля принимаемых наблюдений. |
| Видео, шум, собственный glow | Нет бесконечного curiosity reward и самовозбуждения. |
| VLM timeout/ошибка/unknown | Нет команды ОС, сохранены быстрые рефлексы. |
| Отзыв разрешения | Capture прекращается, базовый пет продолжает работать. |
| Hover/sit/lie/sleep + разные фоны | Энергия течёт, лицо читается, физика/alpha стабильны. |
| Старое сохранение/перезапуск | Память сохранена, transient actions не повторяются, геометрия перевалидирована. |

Метрики: валидное бодрствование без осмысленного эпизода; executed/proposed; завершённость и контекстное разнообразие; навязчивые обращения; skill success до/после на holdout; preference-drift adaptation; угадывание намерения по короткому ролику; CPU/GPU/RAM, p95 latency и frame-time.

Не оптимизировать «процент вне домика» и «количество реакций» напрямую. Сравнить baseline, autonomy fix, autonomy+memory, то же+semantics: вклад каждого этапа должен быть различим.
